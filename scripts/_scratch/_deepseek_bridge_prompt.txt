== ORIGINAL INTENT (from the design chat + architecture docs) ==
- SSM hidden state = WORKING MEMORY = "the currently activated subset of everything the system knows" — a dynamical system whose current activation pattern IS the memory in use. NOT a buffer, NOT a copy. The state is supposed to CARRY query-relevance: "if the retrieval gate detects the SSM state already covers the prompt, no graph retrieval is needed — the answer is already in awareness." Retrieved content is injected INTO the state as embeddings.
- JEPA = (a) pre-training objective: predict the NEXT EMBEDDING (not text/tokens) of the next chunk of meaning, with an EMA target encoder + contrastive negatives, so the backbone learns "semantic continuity"; AND (b) SALIENCE / predictive-coding signal: "predict future retrieval need" / modulate encoding strength ("I'm curious about this -> encode strongly") and routing confidence. JEPA was the CA3-pattern-completion analog: partial cue (current state) -> predict/complete the relevant full latent, and decide when the state is "ready" to answer.
- Text is always kept alongside (HBTrie content store + ring-buffer provenance slot.text). The state never replaces text; "the SSM is the gist, EXPAND is going back to the source."

== SHIPPED IMPLEMENTATION ==
- SSM = ReferenceSSM (NOT Mamba/S4; the Mamba backends are stubs that raise). 4 stacked layers, state [16,384], consumes bge-384 embeddings, input-dependent gated recurrence. d_model=384 = bge-small dim.
- The SERVED backbone (the 19.5M 2a checkpoint + a "text2x" fine-tune) was trained with ONLY the JEPA next-embedding contrastive loss (predict-next-embedding = identity autoencoding). NO relevance objective, NO anaphora objective, NO salience objective was trained into the state.
- JEPA was RETIRED from v1: a 0b probe found a linear next-state predictor beat the JEPA EMA predictor on a "surprise" signal, and because the backbone is frozen at serve the anti-collapse machinery "solves a problem that does not exist." JEPA is reserved for a "future generative rollout." So at serve, JEPA does nothing.
- Relevance/SALIENCE is computed EXTERNALLY by bolt-on heads (bilinear ZRelevanceHead, then a CrossSlotTransformerZHead) reading the frozen identity state's last layer (6144-d = last of 4 layers [16,384]) + the query embedding, ranking ring slots. The gate (retrieval-necessity) reads mean-pool(h_last).
